# Agent Monitor v0.1.2

A read-only iPhone and Apple Watch companion for Hermes Agent on macOS. This release adds the step that was missing from the install story: adding another Mac no longer means copying a server secret by hand.

## Add a computer from the phone

**Agent Monitor → Computers → Add a computer** issues a six-digit code, single use and valid for ten minutes, and shows the exact command to run on the new Mac:

```sh
curl -fsSL https://github.com/wangchangwei/agent-notification/releases/latest/download/install.sh \
  | sh -s -- --url https://your-project.vercel.app --code 123456
```

The code already belongs to your account, so the Mac joins the same owner as the phone and the bootstrap token never leaves the machine that created it. Codes are rate-limited per source address, so a six-digit code cannot be guessed by hammering the bridge.

The bootstrap token still works and is still what the **first** Mac uses, before any phone is paired. Nothing about an existing setup changes: re-running the installer upgrades in place and leaves a registration alone.

## What changed

- **Bridge**: `POST /v1/install-codes` (phone credential) mints a single-use, ten-minute code; `POST /v1/setup` now accepts `X-Monitor-Install-Code` as an alternative to `X-Monitor-Bootstrap`, and joins the owner stored with the code. Failed redemptions are bounded per source address.
- **iPhone app**: a new row under Computers opens a sheet with the code, its expiry, and a copyable command.
- **Probe**: `agent-monitor setup --code 123456` registers with a code instead of prompting for the bootstrap token; `--code` together with `--owner-id` is refused, since the code already carries the owner.
- **Installer**: `install.sh --code` passes the code through and needs no terminal at all, so the whole registration can run unattended.

## Upgrading from v0.1.1

The bridge must be redeployed **before** the new app is built, because the old bridge has no `/v1/install-codes` route and the app would show an error. The probe upgrade is independent: an existing Mac keeps working, and re-running the installer picks up v0.1.2.

## What is included

- **macOS probe** (`agent-monitor`): registers a Mac with the bridge, keeps a durable SQLite queue (7 days, 4,000 events), sends a heartbeat every 30 seconds and uploads state changes immediately.
- **Read-only Hermes plugin**: observes turn start, tool calls, human-input requests and resolution, sub-agent boundaries and session end. It fails open and never alters agent behaviour.
- **Serverless bridge**: FastAPI for Vercel Functions with an Upstash Redis REST adapter, one-time pairing and install codes, per-device revocation, sanitized event history and optional APNs delivery.
- **iPhone app**: SwiftUI, in-app QR pairing, live dashboard, task detail, add-a-computer codes, cloud history clearing, sound and haptic on completion while foregrounded.
- **Apple Watch app**: read-only mirror of running, waiting and finished tasks, with its own copy of the credentials.

## Behaviour worth knowing

- A finished turn means the agent stopped producing for that turn. It does not mean the result was correct or accepted.
- Waiting for input, interruption and an ambiguous session end are reported as their own states; only an explicit failure signal marks a task failed.
- Computer connectivity and task state are independent. A stale heartbeat shows the Mac as disconnected and greys out its last known state.
- Notifications are best effort. APNs may delay, coalesce or drop a message, so opening the app always resynchronizes.
- The probe keeps 4,000 events for seven days; the server keeps the same window per device, and revoking a device deletes its history.

## Privacy

Only fixed state labels, opaque task and turn identifiers, elapsed tool time, a validated tool name, the agent brand, one scrubbed 24-character title and a generic push body leave the Mac. Prompts, tool arguments and results, file contents, paths and conversation text never do. An install code is an opaque six-digit number; it carries nothing but the owner it belongs to.

## Known limits in this version

- Push notifications need a paid Apple developer account: a free personal team cannot sign the push entitlement, so a build installed with a free team shows status but receives no notifications.
- Builds signed with a free Apple team expire after seven days and must be reinstalled.
- An install code is typed, not scanned: there is no QR for adding a computer yet.
- No remote control of any kind: the app cannot approve, reply, cancel or resume.
- Vercel Hobby and Upstash Free have usage limits; this release does not meter quota in the app.
- `install.sh` targets macOS; it refuses to run elsewhere.

## Verification in this release

- The local Python suite passes (40 checks). New coverage: a code joins the existing owner rather than creating one, works once, rejects malformed codes, refuses a Mac credential, is rate-limited after repeated guesses, and leaves bootstrap registration intact; `setup --code` never reaches the token prompt.
