# Agent Monitor v0.1.0

First published release: a read-only iPhone and Apple Watch companion that shows what Hermes Agent is doing on your Mac while you are away.

## What is included

- **macOS probe** (`agent-monitor`): registers a Mac with the bridge, keeps a durable SQLite queue (7 days, 4,000 events), sends a heartbeat every 30 seconds and uploads state changes immediately.
- **Read-only Hermes plugin**: observes turn start, tool calls, human-input requests and resolution, sub-agent boundaries and session end. It fails open and never alters agent behaviour.
- **Serverless bridge**: FastAPI for Vercel Functions with an Upstash Redis REST adapter, one-time pairing codes, per-device revocation, sanitized event history and optional APNs delivery.
- **iPhone app**: SwiftUI, in-app QR pairing, live dashboard, task detail, cloud history clearing, sound and haptic on completion while foregrounded.
- **Apple Watch app**: read-only mirror of running, waiting and finished tasks, with its own copy of the credentials.

Download the wheel for the probe and plugin; the source archive is provided for reference.

## Install

```sh
python3 -m venv "$HOME/Library/Application Support/Agent Monitor/.venv"
"$HOME/Library/Application Support/Agent Monitor/.venv/bin/pip" install "$HOME/Downloads/agent_notification-0.1.0-py3-none-any.whl[qrcode]"
"$HOME/Library/Application Support/Agent Monitor/.venv/bin/agent-monitor" setup --url https://your-project.vercel.app
agent-monitor install-plugin
hermes plugins enable agent_monitor
agent-monitor run
```

Then restart the Hermes desktop app once so the turn-level hooks are rewired, run `agent-monitor pair`, and scan the QR in the iPhone app.

## Behaviour worth knowing

- A finished turn means the agent stopped producing for that turn. It does not mean the result was correct or accepted.
- Waiting for input, interruption and an ambiguous session end are reported as their own states; only an explicit failure signal marks a task failed.
- Computer connectivity and task state are independent. A stale heartbeat shows the Mac as disconnected and greys out its last known state.
- Notifications are best effort. APNs may delay, coalesce or drop a message, so opening the app always resynchronizes.
- The probe keeps 4,000 events for seven days; the server keeps the same window per device, and revoking a device deletes its history.

## Privacy

Only fixed state labels, opaque task and turn identifiers, elapsed tool time, a validated tool name and a generic push body leave the Mac. Prompts, tool arguments and results, file contents, paths and conversation text never do.

## Known limits in this version

- The app interface is Chinese-only.
- Push notifications need a paid Apple developer account: a free personal team cannot sign the push entitlement, so a build installed with a free team shows status but receives no notifications.
- No remote control of any kind: the app cannot approve, reply, cancel or resume.
- Builds signed with a free Apple team expire after seven days and must be reinstalled.
- Vercel Hobby and Upstash Free have usage limits; this release does not meter quota in the app.

## Verification in this release

- Local Python suite covers authentication, one-time pairing, event sanitization, deduplication, retention, clear watermark, revocation, uninstall and the observer plugin.
- iOS state model checks run without a simulator.
- Debug and Release builds compile for both simulator and device SDKs, and the simulator UI was checked visually.
- Not verified in this release: real-device push delivery, and behaviour on a second Mac.
